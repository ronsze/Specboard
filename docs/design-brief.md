# Specboard 디자인 의뢰서

## 1. 제품 개요

**한 줄 설명**: 팀 회의에서 나온 기록과 아이디어를 AI가 출처가 달린 spec 문서로 정리하고, 팀이 점진적으로 완성해 가는 웹앱.

**풀려는 문제**: 애자일 회의에서 정한 내용이 기록으로 남지 않아 나중에 팀원끼리 충돌한다.

**핵심 흐름**
1. 팀원이 입력(회의록, 아이디어 한 줄, 의견)을 제출한다. 제출하면 "대기" 상태다.
2. 관리자가 승인하거나, 사유를 적어 반려한다.
3. 승인된 입력만 재료로 AI가 feature별 spec의 새 버전을 자동으로 만든다.
4. 팀원은 spec의 각 항목이 어느 입력에서 나왔는지 확인하고, 이전 버전과 비교한다.
5. 관리자는 필요하면 이전 버전으로 되돌리거나, 합의된 spec을 확정(잠금)한다.

**신뢰의 핵심**: "출처 추적"과 "AI가 지어내지 않음". 모든 항목에 근거가 보이고, 정보가 부족하면 AI가 단정하지 않고 "미결 질문"으로 남긴다. 이 두 가지가 화면에서 한눈에 느껴지게 해 주세요.

**플랫폼**: 웹 (데스크톱 우선, 모바일 반응형은 일부 화면만). 한국어 UI. 라이트·다크 모드 지원 여부는 디자이너 제안을 받고 싶음.

## 2. 사용자 역할

| 역할 | 할 수 있는 일 | 화면에서 달라지는 것 |
|---|---|---|
| 관리자 (ADMIN) | 입력 승인·반려, 멤버 관리, spec 되돌리기·확정·해제, AI 재시도 | 승인 대기 메뉴, 멤버 관리 메뉴, 되돌리기·확정 버튼 노출 |
| 멤버 (MEMBER) | 입력 제출, 열람 | 제출 폼 노출, 관리자 전용 동작 없음 |
| 열람자 (VIEWER) | 열람만 | 제출 폼도 없음 |

- 화면 어디서나 내 역할이 배지로 보여야 한다.
- 권한 없는 동작은 "비활성 버튼"이 아니라 아예 보이지 않게 하는 방향이 기본이다(디자이너 제안 환영).
- 대기 상태 입력은 관리자와 제출자 본인에게만 보인다. 그 외 사용자의 목록에는 승인·반려된 입력만 나온다.

## 3. 화면 목록

### 공통
1. **로그인**: 이메일·비밀번호, 오류 문구
2. **홈**: 내가 속한 보드 → 프로젝트 → feature 목록, 보드별 내 역할
3. **공통 레이아웃**: 상단 내비게이션(보드·feature 이동, 내 이름, 역할 배지, 로그아웃). 관리자에게만 "승인 대기", "멤버 관리" 진입점

### 입력과 승인 (기능 구현됨, 스타일 재디자인)
4. **feature 입력 목록과 제출 폼**
   - 제출 폼: 종류 선택(회의록, 아이디어, 의견) + 본문. 본문은 한 줄 아이디어부터 긴 회의록까지(최대 50,000자)
   - 입력 카드: 종류, 상태 배지(대기, 승인, 반려, 자동 승인), 본문, 제출자·시각
   - 승인 카드: 승인자·시각. 반려 카드: 반려자·시각·사유가 눈에 띄게
   - 각 입력에 "spec에 반영됨 / 반영 대기" 표시
   - 긴 본문은 접기/펼치기
5. **관리자 승인 대기**: 대기 입력 목록, 승인 버튼, 반려 버튼(누르면 사유 입력 + 확정). 나중에 "기존 결정과 충돌" 경고가 붙을 자리를 확보
6. **멤버 관리**: 멤버 목록, 역할 변경, 멤버 추가(이메일 + 역할), 마지막 관리자 강등 불가 오류 표시

### spec과 버전 (구현 예정, 이 제품의 핵심)
7. **현재 spec 화면** ← 비중 가장 크게
   - 항목 목록: 종류(결정/요구사항), 본문
   - 항목마다 **출처 보기**: 클릭 두 번 이내로 근거 입력(종류, 제출자, 시각, 내용) 확인. 한 항목에 출처가 여러 개일 수 있음
   - **미결 질문** 영역: 열림/해소 구분, 해소된 질문은 답이 된 입력 표시. 항목과 시각적으로 확실히 구별
   - 상태 표시: 갱신 중(진행 중 표시), 갱신 실패(관리자에게 재시도 버튼), 확정됨(확정자·시각), 승인된 입력 없음
   - "승인되었으나 아직 반영되지 않은 입력 N개" 안내
   - 현재 버전 번호와 생성 시각, 이력으로 가는 링크
   - 관리자 전용: 확정 / 확정 해제 버튼
8. **버전 이력과 비교**
   - 버전 목록(최신순): 번호, 시각, 생성 방식(AI 갱신 / 되돌림), 근거가 된 입력
   - 되돌림 버전은 "버전 N으로 되돌림"과 실행 관리자 표시
   - 두 버전 선택 → 비교: 추가, 삭제, 변경 항목 구분 (변경은 이전/이후 문구 대비)
   - 관리자 전용: "이 버전으로 되돌리기" + 확인 단계 (클릭 세 번 이내). 확정 상태에서는 불가 안내
9. **확정/해제 컴포넌트** (7번 안에 포함): 확정 배지, 확정 중에는 새 입력이 "반영 대기"로 쌓인다는 안내, 해제 확인

### 상태 모음
10. **빈 상태·오류 상태**: 입력 없음, 승인된 입력 없음, AI 갱신 실패, 권한 없음(403), 찾을 수 없음(404), 확정 상태에서 되돌리기 시도 안내
11. **모바일 반응형**: 최소 "현재 spec 보기"와 "입력 제출" 두 화면

## 4. 상태별 요소

| 대상 | 상태 | 표시 |
|---|---|---|
| 입력 | 대기 / 승인 / 반려 / 자동 승인 | 배지. 반려는 사유 포함 |
| 입력 | 반영됨 / 반영 대기 | 보조 표시 |
| spec | 없음 / 유휴 / 갱신 중 / 실패 / 확정 | 상태 배지와 안내 문구 |
| 항목 | 출처 1개 이상 | 출처 보기 진입점은 항상 존재 |
| 미결 질문 | 열림 / 해소 | 해소는 답과 출처를 함께 |
| 버전 | AI 갱신 / 되돌림 | 이력 목록에서 구별 |
| 비교 | 추가 / 삭제 / 변경 | 색에만 의존하지 않는 구분 |

## 5. 디자인 요청 사항

- "출처"와 "미결 질문"이 시각적으로 일관된 언어(아이콘, 색, 위치)를 가질 것
- AI가 만든 내용과 사람이 낸 입력을 구별해 보여 줄 것 (입력은 원문 그대로, spec 항목은 AI가 정리한 것)
- 한 줄 아이디어와 수천 자 회의록이 같은 화면에 공존해도 읽기 쉬울 것
- 접근성: 색만으로 상태를 구분하지 않기, 키보드 조작 가능
- 컴포넌트 목록(배지, 카드, 출처 팝오버, 비교 행, 확인 모달 등)과 토큰(색, 타이포, 간격)도 함께 제안해 주세요. 구현은 Next.js + 일반 CSS로 합니다.
