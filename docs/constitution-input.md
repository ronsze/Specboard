# Specboard Constitution 입력

## 프로젝트 개요

Specboard는 팀이 애자일 회의에서 정한 내용이 기록으로 남지 않아 나중에 충돌이 생기는 문제를 해결하는 웹앱이다. 회의록이나 단편 아이디어를 입력하면 AI가 feature별 spec(SDD의 spec 역할을 하는 문서)을 작성하고, 팀원의 의견을 반영해 점진적으로 완성한다.

- 구조: 보드(팀) > 프로젝트 > feature. spec은 feature마다 하나씩 존재한다.
- 형태: 웹앱, 단일 팀 우선.

## 핵심 원칙 (Constitution에 반영할 것)

### I. 모든 내용은 출처를 가진다
spec의 모든 결정·요구사항은 근거가 된 입력(회의록, 아이디어, 의견)과 연결되어야 한다. 출처 없는 내용은 spec에 들어가지 않는다.

### II. AI는 지어내지 않는다
입력이 빈약하면 AI는 내용을 임의로 채우지 않고 "미결 질문"으로 남긴다. 단편 아이디어 한 줄도 유효한 입력이며, 부족한 부분은 질문으로 드러낸다.

### III. 승인된 입력만 반영된다
모든 입력(회의록, 아이디어, 의견)은 제출 시 "대기" 상태이며, 관리자가 승인해야 AI의 재료가 된다. 반려된 입력은 사유와 함께 기록으로 남는다. 관리자가 직접 낸 입력은 자동 승인한다.
- 승인 단계는 입력에 한 번만 둔다. 승인된 입력을 반영한 AI의 spec 갱신은 자동으로 새 버전이 된다.

### IV. 모든 변경은 버전과 이력으로 남는다
spec 변경은 덮어쓰지 않고 새 버전으로 쌓는다. 각 버전은 어떤 입력에서 나온 변경인지 기록하며, 이전 버전으로 되돌릴 수 있어야 한다.

### V. 충돌은 승인 전에 드러낸다
승인 대기 중인 입력이 이미 확정된 결정과 어긋나면 관리자의 승인 화면에서 AI가 충돌로 경고한다. 충돌을 사후에 발견하지 않는 것이 이 제품의 존재 이유다.

### VI. 권한은 보드 단위로 나뉜다
- 관리자: 입력 승인·반려, 멤버 관리, spec 확정
- 멤버: 입력 제출, 열람
- 열람자: 열람

### VII. spec은 spec-kit 호환 마크다운이다
확정된 spec은 spec-kit의 `/speckit-specify` 입력으로 바로 내보낼 수 있는 마크다운 형식을 따른다.

## MVP 범위

- 포함: 보드·프로젝트·feature 구조, 입력 제출(회의록/아이디어/의견), 관리자 승인·반려, AI spec 생성·갱신, 버전 이력과 롤백, 충돌 경고, 마크다운 내보내기
- 제외: 실시간 공동 편집, 외부 연동(Slack, Jira 등), 회의 음성 녹음·자동 전사, 다중 팀

## 아직 정하지 않은 것 (constitution에 넣지 말 것)

- 기술 스택(프론트엔드, 백엔드, DB, AI 모델 제공자)은 `/speckit-plan` 단계에서 결정한다.
