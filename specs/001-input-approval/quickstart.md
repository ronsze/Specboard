# Quickstart: 입력 제출과 관리자 승인 검증

## 사전 준비
- Node.js 22 이상, Docker(PostgreSQL 16 컨테이너용)
- 시드 데이터: 보드 1개, 관리자·멤버·열람자 계정 각 1개, feature 1개 (이번 범위는 가입 기능이 없어 시드 계정만 사용)

## 실행 (구현 후)
1. DB 기동과 마이그레이션, 시드 적용
2. 개발 서버 실행
3. 테스트: 통합 테스트(Vitest) → E2E(Playwright)

구체 명령은 구현 단계에서 `package.json` 스크립트로 확정하고 이 문서에 반영한다.

## 검증 시나리오

| # | 시나리오 | 기대 결과 | 관련 |
|---|---|---|---|
| 1 | 멤버로 아이디어 한 줄 제출 | 대기 상태로 저장, 제출자·시각 표시 | FR-003, FR-005 |
| 2 | 빈 내용 제출 | 거부 | FR-004 |
| 3 | 관리자로 입력 제출 | 즉시 승인, 자동 승인 표시 | FR-006 |
| 4 | 관리자가 대기 입력 승인 | 승인자·시각 기록 | FR-007 |
| 5 | 사유 없이 반려 | 거부 | FR-008 |
| 6 | 사유와 함께 반려 | 제출자가 사유 확인 가능 | FR-008, FR-011 |
| 7 | 승인된 입력 재반려 시도 | 409, 상태 불변 | FR-009 |
| 8 | 두 요청이 동시에 같은 입력 승인·반려 | 한쪽만 성공, 다른 쪽 409 | 엣지 케이스 |
| 9 | 승인 입력 조회 API | APPROVED만 반환, 대기·반려 0건 | FR-010, SC-003 |
| 10 | 열람자 제출, 멤버 승인 시도 | 둘 다 403 | FR-014, FR-015 |
| 11 | 비멤버 열람 시도 | 403 | FR-017 |
| 12 | 유일한 관리자 강등 시도 | 409 | FR-020 |
| 13 | 멤버 B가 입력 목록 조회 (멤버 A의 대기 입력 존재) | A의 대기 입력이 보이지 않음, 승인·반려 입력만 보임 | FR-021 |
